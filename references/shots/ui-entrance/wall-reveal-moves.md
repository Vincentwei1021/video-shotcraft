适用: 功能墙/卡片墙/整页界面的整体亮相；内容已在原位、要"显形"而非"涌入"的段落
时长: 单式约 4.3–5s（A 150f / B 130f / C 150f @30fps，含建立 hold 与静止收尾）
能量: 中

## 意图
"一墙内容怎么出场"库内此前只有 deck-deal-flyin 一个答案——高能量、位移型、
"东西涌进来"。但不是每面墙都该涌：品牌段要庄重、功能墙要轻快、
"从设计到实物"要讲工序。这三式共同点是**非位移批量入场**——元素原地显形，
版式从第一帧就成立，观众看的是"状态变化的波前扫过一面墙"而不是"物体飞行"。
选型先问一句：这面墙该"涌进来"还是"亮起来"？前者去 deck-deal-flyin，后者进本卡。

## 三式选型
| 式 | 做法 | 适用 |
|----|------|------|
| A bento-light-up 逐格点亮 | 暗场 3×2 bento 墙（两行宽窄互补 688/492/492 ↔ 492/492/688，每格一个大字主角）压暗待命，彗星流光按蛇形顺序逐格描边一圈、内容随即提亮上浮，房间随通电变亮，全亮后镜头缓推收住 | 内容庄重/暗场品牌段；节奏沉稳的功能总览 |
| B grid-wave-flip 波浪翻面 | 3×3 卡墙的背面拼成一整块海报（跨格大字），沿对角线波前依次 rotateX 原位翻转 180°，翻出正面功能卡，尾张过冲回弹 | 轻快功能墙；一秒扫完全屏的快节奏段；"口号兑现成功能" |
| C wireframe-draw-on 蓝图描线成形 | 界面先以细线蓝图分组描画（方块描线 + 空心描边字写出 + 尺寸标注），再一条发光竖线左→右扫过，扫过处线框实体化成真实界面 | "从设计到实物/从想法到产品"叙事；产品首次整体亮相 |

## 参数表
| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| A 节拍 | 首格 18f 起，每格间隔 12f 蛇形点亮（上排左→右、下排右→左；六格 ~84f 全亮）→ 98–128f 缓推 0.972→1（smooth，落点即设计版式）→ 静止收尾 22f | 12f 等距是"逐格可辨"与"整墙拖沓"的平衡点，间隔均匀本身就是这一式的庄重感来源，别学发牌加速；蛇形顺序让光像一根电线走完整面墙，下排彗星从右上角起跑接住上一格 |
| A 单格 | 暗态：卡体 brightness 0.55、内容 opacity 0.12 + 去饱和（版式第 1 帧就在）；彗星 12f 一圈（smooth），头部沿 pathLength=100 走 0→126，26% 拖尾按三层递减宽度/透明度伪造渐变，亮芯白→玫粉 + 头部 120px 泛光点（按圆角矩形周长求坐标）；身后留 1.5px 细边，+22f 退火到 0.28 常亮；+6f 内容 12f 提亮、上浮 22px 带一次过冲，主角数字/图形再晚 3f | 描边与内容弹出要**接力不同步**——同帧起读作整格闪现；拖尾追上头部自然收掉，比硬淡出干净；房间（舞台主光）按已点亮格数连续爬升，最后一格亮完全场到满 |
| A 内容 | 每格只讲一件事：38s / 212 / 99.99% / 分支 URL / SOC 2 / 84ms，主角字 112–140px 白→薰衣草渐变字，要读的辅助字 ≥32px | 满屏小字 dashboard 卡在点亮时读不出"亮了什么"；一格一个大字，点亮就是信息 |
| B 波前 | 0–12f 海报 hold → 12–28f 一道斜向柔光沿对角线扫过海报（预示波前方向，全墙仅此一次）→ 首张 24f 起，delay=(row+col)*6f，每张 16f bezier(0.5,-0.22,0.3,1)（先微仰 ~6° 再翻）；尾张冲到 192° 再 10f 弹回 180° | (row+col) 是对角波的灵魂，换 row 或 col 单向扫立刻平庸；只给尾张过冲——张张过冲读作整墙果冻 |
| B 背面海报 | 九张背面共用一张 1616×872 的钴蓝海报（跨格 290px 粗黑体 Plan. / Build. / Ship. 左中右错落 + 细网格 + 行号小字），每张背面只渲染自己格位那一块（按 -col/-row 偏移裁切），格缝把大字切开 | 第 1 帧就是一张完整海报，不是灰块待命；正面按海报三行分组（PLAN/BUILD/SHIP），墙心一张钴蓝实底主角卡做收尾重心 |
| B 翻面结构 | 整墙一个消失点：每格自带 perspective 2200px、perspectiveOrigin 换算到整墙中心；按角度显式只画朝外那面（<90° 背面，≥90° 正面以 angle−180 旋转），不依赖 backfaceVisibility（Chromium 会把首行/首列的背面也剔掉）；朝向偏离镜头时按 cos(角度) 压暗 | 各格 perspectiveOrigin 不换算到墙心，九个消失点各翻各的；perspective 太小（1200）边角格近缘会甩出格位；翻到 90° 最薄处叠一道 3px 白色高光线（不随卡旋转、随角度 50°→130° 从上缘扫到下缘），格位下方独立地面影随 sin(angle) 抬起变大变虚再收回 |
| C 描线 | 0–14f 点阵 + 四角裁切标记 → 8f 窗口外框 30f → 侧栏 18f 起逐项 +4f → 页头 28f → 主数字/KPI 36f → 图表网格 44f、曲线 50f；方块 SVG pathLength=1 + dashoffset 1→0（铅笔灰，外框 1.6px / 内件 1.2px），文字是同位置的空心描边字（-webkit-text-stroke）按 clip 从左往右"写"出；56–84f 尺寸标注（1600 / 880 / 56，香槟金等宽小字） | 分组错峰是"手在画"的感觉来源，全部同帧起笔读作打印机；线框与实体来自同一张几何表（方块/文字/图表坐标共用），不存在对位误差 |
| C 实体化 | 92–124f 实体层 clip-path 前沿 = scanX（120→1800px，bezier(0.55,0,0.25,1)）；3px 白芯 + 香槟金辉光竖线 90–96f 淡入、120–128f 淡出；竖线身后 300px 一段渐隐暖光（只在窗口内，上下羽化）；前沿正前方 220px 的线框先被预照明成暖色；尺寸标注在扫描线经过时熄灭 | 竖线位置与 clip 前沿必须同一个 scan 值驱动，异步读作穿帮；描线段与扫描段之间留 ~8f 喘息（84→92f），线框画完立刻扫读作赶工 |
| 静止收尾 | 三式动作全部落定后静止 ≥15f（A 在缓推结束后；B、C 落定后只剩整墙 1.025–1.03 的极缓推进，分别到 110f / 132f 收住后真静止） | R1 呼吸判例：静止期一切属性锁死，包括辉光/阴影/高光残留 |

## 已知坑
- **demo 在为镜头手搓的虚构 UI 上调校通过——参数是调校起点非实战定稿，
  首次实战须以真实素材回验**
- A/C 的强调色描边/扫描线属"单点高质量光效"范畴（Q4 三约束内合规），但一支片
  整墙点亮 ≤1 次（P4 手法去重）——A 和 C 同片共用即算两次整墙光效，选一
- B 式翻面后的正面实战要接真实截图：backface 侧预留高清纹理（Q2），翻转中
  正面会以斜角被看，低倍截图先按审美准则 Q2 的高分辨率栅格化技法处理再上
- C 式线框几何必须与实体层布局逐像素对位（demo 里线框与实体共用一张几何表，文字直接用同位置描边字），
  换素材也要走同源几何——对不齐则扫描线扫过瞬间元素跳位，一眼穿帮；空心描边字在部分字形
  （如 SF 的 M、$）会露出轮廓重叠的内线，属蓝图味可接受，介意就换描线占位条
- 三式都是"原位显形"，别混入位移入场（如 B 翻面时再加 translateY 飞入）——
  位移需求去 deck-deal-flyin，杂交会两头不像
- A 式暗态（内容 0.12 + 卡体 brightness 0.55）依赖暗底成立，亮底下压暗读作褪色故障
