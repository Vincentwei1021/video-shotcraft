---
name: typing-code-block
一句话: 同一段语法高亮代码左右并置两种 reveal——左侧行级 stagger 9f 去虚上浮 14px，右侧逐字符打字但字符保持原 token 色，当前字符垫一块发光方块光标
适用: 代码/配置揭示镜头；开发者产品的"就三行"演示；需要对比两种揭示节奏时的选型参考镜
时长: 165f（5.5s@30fps）
能量: 中（右侧持续打字推进，左侧一次性收敛）
---

## 意图
代码揭示只有两种真解法：**整行浮出来**（读的是结构）和**一个字一个字打**
（读的是过程）。这卡把两者并排放在同一段代码上，是选型用的对照镜：
左侧 4 行 4 拍（1.6s）就完，适合"代码不是重点、结果才是"；右侧 3.6s 才打完
71 个字符，适合"看我写"。关键细节是右侧**打字不丢色**——常见错误是
打字时先出白字再着色，那就退化成终端回显，不是代码编辑器。

## 动效核心
- 舞台：aurora 紫黑暗场（顶部紫光 + 右下粉色余光 + 稀疏浮尘），两块同规格 820×500 编辑器玻璃面板
  并排（间距 56，合占画宽 88%），面板上方 44px 标签「01 Line by line / 02 Keystroke」，
  下方各一条揭示时间线（左 4 段刻度随行点亮、右连续进度条）+ 32px 计数与秒表——两种节奏差直接画出来
- token 模型：每行是 `[[文本, 颜色], …]`，6 色板（关键字 #b69cff、标识 #f1ecff、函数 #ff8fc8、
  字符串 #8ff0c8、标点 #9a90bb、注释 #6f6590），代码 40px 等宽、行高 70
- **左侧行级 stagger**：第 i 行 `ramp(f, 16 + 9i, 20, snappy)`，`opacity = k`、`translateY = (1-k)·14`px、
  `blur = (1-k)·6`px；行号随行一起亮
- **右侧逐字符**：每字符出现帧是确定性 1/2f 间隔表（均 ~1.45f），换行处多顿 4f；每个字符 span
  建的时候就带 token 色，打到时只翻可见性——**着色在 setup 期完成，render 期不碰颜色**
- 光标是背景块不是竖线：`i === typed` 的字符垫强调色发光方块、字反白（onAccent）——下一个待打字符
  先以色块占位，块往右挪即是光标移动；当前行整行淡高亮 + 左缘 3px 强调色条，行号随该行开打点亮
- 右侧打完状态栏 Typing… → ✓ Saved，面板一次扫光（Q4：只给主角一次）；相机全程 1→1.025 极缓推
- 右侧行 `min-height: 行高` 撑住空行——不撑的话未打的行高度为 0，面板内容会随打字往下长（跳版）

## 参数表
| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| 代码量 | 4 行 / 71 字符 | 打字时长 ≈ 字符数 × 1.45f + 换行顿；超过 6 行面板要缩字号，超过 100 字符右侧打不完 |
| 行 stagger | 9f，单行窗 20f snappy | 9f 读得出"逐行"又不拖；<5f 四行齐亮没有 stagger，>20f 最后一行等太久 |
| 行位移 | `(1-k)·14`px 上浮 + 6px 去虚 | 代码块该有的克制幅度；>20px 行像卡片飞进来，抢了代码本身 |
| 打字节奏 | 确定性 1/2f 间隔（55% 为 1f），换行 +4f，f18 起 f131 止 | 匀速每帧一字读作复制粘贴；结束留 ≥30f 静置读全文 |
| 光标块 | 强调色 #a78bfa 背景 + 18px 泛光，字反白，仅当前字符 | 方块光标是编辑器语感；换成竖线要另加闪烁，代码块里反而更碎 |
| 面板 | 820×500、紫黑纵向渐变玻璃、14% 发丝边、圆角 24、40px/70 行高 | 两侧必须同规格，尺寸不一就不是对照而是两个镜头 |
| 空行占位 | 右侧行 `min-height: 70px` | 不设则面板随打字长高，整块跳版——这是本卡最容易漏的一处 |

## 已知坑
- demo 在灰阶/占位素材上调校通过——参数是调校起点非实战定稿，
  首次实战须以真实素材回验
- **换成项目代码时字符总数要贴近 71**：右侧打字时长随字符数线性增长，
  代码翻倍就打到片尾都打不完，代码减半则右侧早早收完、对照失去意义——
  改代码量必须同步调时长或间隔表，别只换文案
- 着色必须在 setup 期写进每个 span：render 期改色（先白后染）会把
  "代码编辑器"降级成"终端回显"，这是同类效果最常见的失手
- 左侧行级淡入与右侧逐字符**不同步**（左侧 4 行 f63 就收完，右侧要打到
  f131），这是对照镜的本意；若实战只留一侧，另一侧的时间窗要重新铺满全片
- token 数组是手写的，没有真词法分析——换代码时得手动切 token；
  切错色比不着色更糟（关键字被染成字符串色，懂代码的观众立刻出戏）
- 实战里通常**只留一侧**：对照版是选型镜，正片里两块面板一起动会分散
  注意力，选定手法后单面板居中放大
