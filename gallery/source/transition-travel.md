## 意图
shot-transitions 六式是"交棒"型——前镜收尾、后镜入场，接缝靠白闪/暗场/
焦点/黑场/糊帧/窗口盖住换页瞬间。本卡两式是"穿越"型——后景在前景画面里
以真实元素存在（网格槽位/字形洞），镜头一条连续空间运动钻进去，
观众从头到尾跟着同一个物体，没有交棒瞬间。选型口径：后景能在前景里"预先
在场"→穿越；两景只是先后关系、无空间嵌套→交棒。两式内部再按语义分——
A 是"把这张卡放回去"（详情→总览，F 式穿窗的逆向）；C 是"标题即是门"
（章节字卡与转场二合一）。

## 两式选型表

| 式 | 做法 | 适用接缝 |
|----|------|----------|
| A 共享元素归位 shared-element-morph | 全屏特写卡收缩+位移+长出圆角，严丝合缝飞落进总览网格所属槽位，一次轻过冲落座、邻卡被"撞"出一圈涟漪 | 详情→总览的"归位"语义；与 F 式穿窗成对使用（进窗/回位）|
| C 字腔穿越 letterform-zoom | 巨型标题字形（SVG mask 挖洞）透出新页，指数推进穿洞，洞撑满瞬间接管、残余笔画甩出画外 | 章节标题→正文；替代 D 式黑场字卡的高能量款 |

## 参数表
| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| A 卡片比例 | 槽位卡做成 16:9（demo 528×297，3×2 网格 x 128–1792 / y 330–964），全屏特写 = 这张卡 ×3.64 本身 | 比例不等于画面比时全屏要裁切，特写里的标题/信息会被切掉；16:9 卡让"特写"零重排 |
| A morph 主曲线 | 位置/尺寸/圆角共用一条弹簧进度 p（damping 7.6 / stiffness 26：~21f 首次到位、峰值 ≈3%）；过冲段再按 0.3 压缩 | p 的 3% 换算到卡片尺寸是 8%（全屏→小卡差值大），不压缩就读作"缩过头的果冻"；三属性各走各的曲线立刻读作"变形"而非"同一物体" |
| A 同一物体感 | 内容按槽位尺寸排版、外层 CSS `zoom = w/528` 等比放大（Q2：布局级放大，特写里 132px 标题不糊）；投影 softShadow 从 56 收敛到 4 | 内容重排版=换了张卡，穿越感断；投影不收敛则卡永远悬空、落不了座 |
| A 起飞因果 | 特写左上「‹ Saved trips」返回键 22–27f 按下（缩 8% + 提亮）、整卡轻吸 1.5%，28–36f 特写 chrome 淡出，34f 起飞 | 无"按返回"则卡片自己飞走、没有动机；chrome 不先撤会被一起缩进槽位 |
| A 落座仪式 | 背景网格 1.035→1 后拉（原点=槽位中心，p≥1 严格 1）；邻卡飞行中 0.5 透明 + 去饱和待命，落座帧起按距离错峰提亮并被径向推开 11px（e^(−t/6)·sin(t/2.6) 两拍收敛） | 背景全程满亮则飞落没有"到家"的一拍；涟漪 >16px 读作网格散架 |
| C 穿腔主推 | 盖板 SVG mask（白底+黑字 900 字重）挖洞，transform-origin 对准字形笔画（洞）中心——锚在字腔里推到底撑满的是盖板不是洞（demo：「SHIFT」560px 的 I 竖笔中心 1029,515，竖笔 107px×30 > 画宽）；scale=30^u，u 52f bezier(0.6,0,0.85,0.5) 慢起陡收，推前 26–34f 后吸 2% 预备 | ZOOM_MAX 按"洞撑满画面"配，笔画越细倍数越大；慢起段留给观众看清"洞里有东西" |
| C 洞里有东西 | 盖板暗、洞里亮：暖黑盖板 vs 熔金渐变发布页，洞里的卡片也做成亮面（奶白磨砂）；字缘一圈模糊橙色描边只画在盖板区域（光从洞里漏出来）+ 1.5px 暖白切口边 | 洞里有深色块时那几个字母读作"实心字"，穿洞的悬念就没了 |
| C 洞里只给光不给字 | 字卡 hold 期页面的文字/卡片层完全隐去，洞里只透出暖色渐变 + 柔光形（卡片位一团奶白光、标题位一抹暗赤）；主推中段 64–90f 内容层由 18px 失焦淡入合焦（EASE.out），接管时已清晰 | 洞里能读到页面标题时，两层可读文字互相抢，标题字读作"杂乱"而不是一个干净的镂空 |
| C 撤场与拖影 | scale∈[14,26] 盖板 opacity 1→0；u>0.35 起期望模糊 0→20px（除以 scale 写进 blur）+ 四层更早 0.8–3.2 帧的半透明盖板残影叠成径向变焦拖尾；接管瞬间页面 brightness +12% 一闪回落 | blur 不除 scale 会被放大成糊墙；只用两层残影会读成硬边半透明色块，四层才连成拖尾 |
| C 后景视差 | 页面只推 1→1.08（主推期 0.7·u，接管后 quint-out 补完，交接处速度连续）+ 0–100f 向左漂 28px；接管后页面上的计数 0→32、延迟条错峰填满、LIVE 标签弹出 | 后景不动则洞里是张死图；后景推太多会和盖板同速，纵深消失 |

## 已知坑
- C 式推进锚点要按渲染帧实测（demo 的竖笔坐标是从静帧量出来的），换字体/换词/渲染器字距
  不同都会漂——渲后看推进方向，洞不居中就微调 origin，别信字宽 em 值手推的数
- C 式后景页面推到 1.08 时四周会被裁掉 4%：版面安全边距要按"推完后"留（demo 左右 200/230、顶 122）
- A 式槽位坐标必须精确到像素（demo 由 GX/GY/CW/CH/GAP 常量直接算出 slotOf(4) = 696,667,528×297,r22）——
  差几像素落座后再对齐，观众读作"飞到附近再吸附"，"归位"的严丝合缝感全无
- A 式过冲段别直接用 p 的原值：全屏→小卡的尺寸差把 3% 放大成 8%，要单独压缩
- 穿越两式与交棒六式同一接缝不叠加，一缝一式；穿越式已自带高能量，
  再包白闪/震屏读作穿帮（规矩同 shot-transitions）
