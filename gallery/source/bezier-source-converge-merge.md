name: bezier-source-converge-merge
一句话: 左侧四个来源节点各有一条贝塞尔光路连向右侧同一汇聚点，光路先错峰由左向右 draw-on，节点沿自己的曲线错峰滑向汇聚点并三段式加速缩小、化成光点被吸入，强调色数据包沿路径滑行，吞并完成后光路从左端反向擦除、相机把徽标收到正中只留徽标与结论句
适用: "多源整合/统一接入/数据汇聚"的核心机制镜头；集成、聚合、单一入口类产品的说明段落
时长: 约 5.6s（168f@30fps）
能量: 中（长镜慢速推进，靠数据包滑行维持活性；四路错峰吞并的连打是唯一高点）

## 意图
"我们把四个来源统一了"是一句抽象话。这个动效把它变成可看的物理过程：先建立四条独立
的通路（draw-on 是"连上了"），再让四个来源真的顺着通路走进同一个点并被吸进去（缩小
到 0 是"被吞并"），最后擦掉通路只留徽标（"现在只有一个"）。三段叙事各自有明确的
起止，观众不需要旁白就能读出因果。

## 动效核心
（demo 版本：极光暗场数据汇流，1920×1080 原生坐标，来源砖 128px、汇聚徽标 168px）
- 路径几何：每条 `d = "M -40,y L 540,y C 940,y 980,540 1440,540"`——起点在画框外 -40，
  540 处是来源节点的驻留位，之后一段水平出、水平入的三次贝塞尔弯向汇聚点 (1440,540)。四条只差起始 y
  （300/470/640/810），所以曲率与汇入角天然不同
- 光路两层：10px 低透明度强调色柔光底 + 2.4px 渐变细线（来源端暗紫 → 汇聚端亮粉，读出流向）；
  draw-on 用 `dasharray = len` + `dashoffset = len·(1-draw)`，`ramp(f, 6+i*5, 26, out)`——5f 错峰
  让四条线像被依次接通
- 节点定位用弧长参数化（直线段定长 580 + cubic 1600 段累积弧长表二分反查，模块级预计算、无 DOM 依赖），
  `f0 = 580/len`，运行时 `frac = f0 + (1-f0)·conv`——节点**沿真实曲线**走，不是两点插值
- 四路错峰汇入：`conv_i = ramp(f, 52+5i, 56, E.inOutCubic)`，到达帧 108/113/118/123——徽标被连打
  四下（da-da-da-DUM），每下 `sin` 包络 +7%（末下 ×1.6），泛光强度 `0.35 + 0.16·已吞路数` 逐级抬高，
  外圈四段弧逐段点亮，右上计数 `N / 4 SYNCED` 同步
- 三段式缩小：`conv < 0.75` 时 128→44px（缓慢瘦身），`conv ≥ 0.75` 时 44→0（最后 1/4 行程掉光）——
  后段尺寸变化率是前段的 4 倍多，这就是"被吸进去"；`conv 0.35→0.5` 时砖面被强调色径向光"点燃"、
  圆角 0.26→0.5 收成光球，读作化成光被吸入；名称在汇入开始时向左退场 + 退焦
- 数据包：`pkCycle = (ramp(f, 24, 80, linear)·2) % 1` 走两个整数周期，各路加 `i*0.13` 相位偏移；
  白色亮点 + 12 段粉色彗尾，透明度 `1 - |cycle-0.5|·0.7` 让包在路径中段最亮、两端淡
- 擦除：`erase = ramp(f, 114, 20, swift)` 把 dashoffset 推成负值（`-erase·len`），虚线从**起点**方向退走；
  同时相机 118→146f 平移 480px + 推近 1.1（smooth）把徽标收到画面正中；末次吸入同拍一圈涟漪扩到 3.2 倍
- 结论句 "One source of truth."（96px/700）128f 起逐词升起，副句 36px 跟随；146–168f hold

## 参数表
| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| 来源数 | 4 条（y=300/470/640/810，间距 170） | 4 条是曲率差异明显又不打结的甜点；>6 条中间几条的贝塞尔几乎重合，汇入角读不出区别 |
| draw-on | 起点 `6+i*5`，窗 26f，out | 5f 错峰；归零会读作四条线一起刷出，失去"逐路接通"的语义 |
| 汇聚窗 | 每路 56f（inOutCubic），四路错峰 5f | inOut 的缓起是"启动"、缓收是"到位"；错峰归零四路同时到，徽标只被打一下，节奏变平 |
| 三段缩小 | 128→44px（前 75%）→ 0（后 25%） | 拐点越靠后吸入越突然；挪到 0.5 会变成"一路缩小"，吞并的那一下就没了 |
| 点燃 | conv 0.35→0.5，圆角 0.26→0.5 | 点燃太早砖面图标还没读清就变光球；太晚（>0.7）吸入时仍是一块砖，读不出"化成数据" |
| 数据包周期 | 2 个整数周期（24→104f 线性） | 必须是整数周期，否则收包时停在半路；加密到 4 会读作数据流很急，也更容易和节点重叠 |
| 包相位偏移 | `i*0.13` | 错开四路的包，避免排成一行同时汇入 |
| 擦除 | 114→134f，dashoffset 取负，swift | 必须在第一路吸入（108f）之后开始，否则线先没了节点悬在空中 |
| 徽标脉冲 | 每下 +7%，末下 ×1.6 + 涟漪 3.2 倍 | 7% 是"接收到了"的量级；>15% 会抢过汇聚本身的注意力 |
| 结尾相机 | 平移 480px + 推近 1.1，28f smooth | 不平移的话结尾徽标偏在右侧三分线，结论句无处安放 |

## 已知坑
- 原 motion-lab 版用 `getTotalLength` / `getPointAtLength`，必须在 SVG 已挂到文档且完成布局之后才有效，
  移植到 Remotion 时首帧渲染可能拿不到长度。demo 改为模块级预计算弧长表（纯函数、无 DOM 依赖），
  改路径时只要同步改 `cubic()` 的四个控制点与 `pathD()`
- `f0` 直接按直线段长标定（`LINE_LEN/len`，demo 为 580）。旧版用 40 步线性扫描，精度只有 1/40，节点驻留位
  会偏离驻留位、四个节点排不成一列——改路径（尤其直线段长度）后要同步改这个标定
- 节点不做淡出：conv 到 1 时尺寸恰好缩到 0，节点是在尺寸缩到 0 时消失而不是淡出消失。这是有意的（被吸进去不该淡出），但如果把三段式
  拐点改晚，会看到节点在有尺寸时突然消失
- 节点是深色玻璃砖 + 白色线性图标（数据库/云/表格/API）的占位，落地要换成真实来源 logo；
  强调色只留给光路、数据包、点燃态与徽标，不要给静置的节点上色，否则汇聚点的视觉主体被夺走
- 汇聚点 (1440,540)、结尾平移量 `PAN = XC - 960` 与路径控制点是绑定的一组坐标。改汇聚点位置要整套重标，
  路径起点 -40 依赖 SVG `overflow:visible` 才能露出画框外的一截
- 结论句 "One source of truth." 出现在 128f 之后——如果要配旁白，这句的
  出现点应对齐旁白落词而非动画节点
